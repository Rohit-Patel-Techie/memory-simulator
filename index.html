Aim

To Simulate and Analyze Contiguous Memory Allocation Techniques—First Fit, Best Fit and Worst Fit in a Fixed Partitioned Memory Environment and to evaluate their impact on Internal and External Fragmentation.

Theory & Applications

Memory management is responsible for allocating and deallocating memory space to processes efficiently.

The operating system maintains a list of free memory blocks (holes) and allocated blocks, and must decide which free block to assign when a new process arrives using allocation strategies such as First Fit, Best Fit and Worst Fit.


The main memory is a combination of two main portions - one for the operating system and the other for the user program.

Contiguous Memory Allocation: Contiguous memory allocation is basically a method in which a single contiguous section/part of memory is allocated to a process or file needing it.

Non-Contiguous Memory Allocation: Non-Contiguous memory allocation is basically a method on the contrary to the contiguous allocation method, allocating the memory space present in different locations to the process as per its requirements.

Difference Between Contiguous and Non-Contiguous Memory Allocation

S.No. Contiguous Memory Allocation Non-Contiguous Memory Allocation
1 Allocates a single, consecutive block of memory to a process. Allocates separate, scattered blocks of memory to a single process.
2 Faster execution time and easier for the Operating System to control. Slower execution time and highly complex for the Operating System to manage.
3 Minimal overhead due to simple and limited address translations. High overhead because the system must perform numerous address translations.
4 Implemented using Fixed (Static) Partitioning or Dynamic Partitioning. Implemented using techniques like Paging and Segmentation.
5 Easily visualized and implemented in code using Arrays. Typically implemented using complex structures like Linked Lists.

Key Concepts

  • Fixed Partitioning (Static Allocation): The RAM is divided into fixed-size blocks before execution. A process is allocated to a single block and no block can hold more than one process.
    • Degree of Multiprogramming: Strictly limited by the number of partitions created.
    • Process Size Limit: A process size cannot exceed the size of the single largest partition in the memory map.
    • Data Structure: Managed using a static Partition Description Table (PDT) array to track the allocated or free status of each block.
  • Allocation Algorithms
    • First Fit: Allocates the first available partition that is large enough to hold the process. It is fast and requires minimal searching, but often leaves larger blocks heavily fragmented early on.
    • Best Fit: Searches the entire list of partitions and allocates the smallest available partition that fits the process. It minimizes wasted space within the chosen block but requires more CPU time to search.
    • Worst Fit: Allocates the largest available partition. The logic assumes the leftover space will be large enough to hold another future process though it quickly degrades overall memory utilization.
  • Fragmentation Types
    • Internal Fragmentation: Occurs when a process is allocated a memory block larger than its requested size. The leftover space strictly inside that specific block is permanently wasted.
    • External Fragmentation: Occurs when the total free memory across the system is sufficient to satisfy a process request, but the memory is not contiguous (it is scattered across multiple blocks), causing the OS to reject the process.

Applications in the Real World

  1. Legacy Mainframe Operating Systems: IBM's OS/360 utilized fixed partitioning (MFT - Multiprogramming with a Fixed number of Tasks) for early batch processing environments.
  2. Embedded Systems: Hardware with strict, unchanging memory constraints often uses fixed memory mapping to guarantee critical system processes always have reserved execution space without dynamic overhead.
  3. Custom Software Memory Allocators: High-performance C++ applications and game engines often bypass the OS to build custom memory pools utilizing variations of First/Best fit to manage memory manually.
Procedure

This section provides step-by-step instructions for using the Fixed Partitioning Memory Allocation Simulation and understanding how First Fit, Best Fit and Worst Fit allocate memory to processes.

Steps for Initial Setup
  1. Navigate to the Practice section of the V-Lab website.
  2. Observe the initial memory blocks displayed in the Memory Blocks Visualization area.
  3. Note the predefined memory block sizes (e.g., 100 KB, 500 KB, 200 KB, 300 KB and 600 KB) and the process sizes.
Steps for Executing Allocation Algorithms
  1. Enter Memory Blocks: Enter positive memory block sizes in KB, separated by spaces.
  2. Enter Process Sizes: Enter the process sizes in KB, separated by spaces. The simulator automatically assigns process IDs such as P1, P2 and P3.
  3. Select Algorithm: Choose First Fit, Best Fit or Worst Fit using the algorithm buttons.
  4. Start Allocation: Click the Allocate button once to start the automatic simulation.
  5. Observe how the simulator checks memory blocks, highlights the blocks being examined and updates the allocation status.
Steps for Analyzing Memory Utilization and Fragmentation
  1. Observe which memory block is selected for each process and compare the selection logic of the three algorithms.
  2. Examine the allocated blocks to identify Internal Fragmentation, which is the unused space remaining inside an allocated fixed partition.
  3. Review the Memory Statistics section to compare total memory, used memory, free memory and internal fragmentation.
  4. Observe whether any process remains unallocated because no single free memory block is large enough to accommodate it.
  5. Click the Reset button, select another algorithm and run the same inputs to compare allocation decisions and memory utilization.
